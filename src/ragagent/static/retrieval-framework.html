这张图按真实代码执行顺序绘制。框是执行节点，箭头标签是节点之间传递的状态对象；节点内部左侧是输入字段，右侧是输出字段。示例数字用于解释路径，但字段名、Top K、阈值和路由与当前实现一致。

只有一个 Canonical Query它是全局语义标尺：用于统一 rerank、Evidence Gate 和最终回答；不会为每条召回 query 各生成一次答案。
Retrieval Queries 可以有多个它们只负责扩大召回面。每条 query 独立执行 Dense + BM25 + RRF，再合并去重。
Evidence Gate 是最后一道控制门它收到已经选好的 Evidence Set，输出 answer / retry / clarify；retry 会回到召回阶段，但总检索轮次最多 2。

BOUNDARIES

三个最容易混淆的点

误解：每条 query 都各自 rerank、各自回答。实际：每条 query 只召回；合并后仅使用 canonical query 做一次 Global Rerank，最后只生成一次答案。
误解：Gate 看 Top6，生成时又重新选上下文。实际：先构造 EvidenceSet，再让 Gate 审核；answer 后同一个 EvidenceSet.hits 原样交给生成模型。
误解：会话记忆也是证据。实际：记忆只帮助 Query Understanding；事实回答必须重新从知识库召回并进入 EvidenceSet。

一句话：Retrieval Queries 负责“多找”，Canonical Query 负责“统一判断”，EvidenceSet 负责“确定上下文”，Evidence Gate 负责“决定能不能回答”。
